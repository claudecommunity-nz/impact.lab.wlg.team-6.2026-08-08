# Kitea — presentation talking points

Deck: `web/presentation.html` (arrow keys / space; `F` fullscreen; `P`
prints to PDF). Twelve slides, ~3 minutes.

1. **Title.** Kitea, "seen" in te reo — the promise is the name: your
   report has been seen. Working name, pending mana whenua review.
2. **The problem.** A third of an event's call-centre volume is status
   checks. Every one is a failure of acknowledgment, not information.
3. **The idea.** Delivery tracking, not a support ticket. Report in a
   minute, watch it happen, the council acknowledges by acting.
4. **One live map.** Community reports beside official agency data; the
   lens is the question the visitor is asking.
5. **Reported, tracked, verified.** Provenance is the visual language;
   verification is an explicit, recorded act that promotes a pin to
   official — live, in front of everyone.
6. **The council console.** Triage, hazard context, one tap to verify or
   set status; Comms publishes to the public map; Access is named,
   role-based keys; an admin can declare emergency mode.
7. **Any phone, one minute.** No account, no app; a reference code is the
   only credential. Designed for a stressed phone in bad weather.
8. **Real data, honestly labelled.** Six live agency feeds, each showing
   its own freshness. Inference is never presented as fact.
9. **Inclusion by construction.** No login; local fonts so it survives a
   dead venue wifi; report on someone's behalf; the deprivation signal
   surfaces where need concentrates.
10. **Built to be adopted.** Zero runtime dependencies, runs inside the
    council's own boundary, data never leaves, append-only audit trail.
    Certified Production Ready.
11. **Working as one.** The horizon: agencies as first-class actors, the
    council requesting help, notification tiers, a standing skills
    register. One picture in an emergency; the same loop every day.
12. **Close.** Live at kitea.bitn.co.nz. In an emergency, call 111.
